# ESP32 Audio EQ

基于 ESP32 的 48 kHz / 24-bit 立体声 I2S 音频 EQ。音频路径为：

```
ADC --I2S--> ESP32 --EQ/延迟--> ESP32 --I2S--> DAC
```

每声道最多 50 段 peaking biquad。Web 页面用于编辑左右声道 EQ，保存后热加载，
无需重启。工程使用 ESP-IDF 6.0.2 开发，目标芯片为 ESP32（Xtensa LX6，240 MHz）。

## 主要特性

- 48 kHz 采样率，32-bit I2S 槽位，24-bit 有效数据
- 每声道最多 50 段 EQ，`float` 双二阶滤波器
- 左右声道独立配置，NVS 持久化
- `Swap L/R` 声道交换选项，可适配实际接线反相
- 保存后热加载，不重启
- 可选的左右相对延迟（最多 256 帧，约 5.33 ms）
- 稳态音频热路径不输出日志（保存时仅打印一行重载摘要）

## GPIO 连接

| 功能 | GPIO | 说明 |
|---|---:|---|
| MCLK | 0 | 12.288 MHz（256 fs） |
| BCLK | 27 | 3.072 MHz（64 fs） |
| LRCK / WS | 26 | 48 kHz |
| DOUT | 25 | ESP32 -> DAC |
| DIN | 23 | ADC -> ESP32 |
| Wi-Fi/HTTP 开关 | 33 | 数字输入，长按高电平 ≥3 秒切换 |
| 状态指示 | 2 | Wi-Fi/HTTP 开启时为高电平 |
| 功放控制 | 16/17/18 | 板级功放控制，具体电平以实际电路为准 |

注意：

- GPIO33 在代码中是普通数字输入（`gpio_get_level`），不是 ESP32 裸电容触摸
  焊盘。如果板上是裸触摸焊盘，需要外部触摸模块输出数字电平，或改用触摸 API。
- 代码未显式配置 GPIO33 的内部上拉/下拉。请确认板上有外部上下拉，避免悬空误触发。
- GPIO18 不再用作 PWM 输出，现在是普通功放控制脚。

## Wi-Fi 与 HTTP 开关

上电后 GPIO33 默认为输入。主循环每 500 ms 读取一次：

1. 检测到高电平后等待 3 秒；
2. 再次确认为高电平后，切换 Wi-Fi/HTTP 状态；
3. 切换后等待 3 秒，避免立即重复触发。

即：**第一次长按启动，第二次长按关闭**。如果一直保持高电平，会大约每 6.5 秒
反复开关一次。

启动后：

- SSID：`ESP32-AP`
- 密码：`123456789`
- 地址：`http://192.168.4.1`
- 最多 5 个客户端

## HTTP 接口

只保留两个编辑入口，每个入口同时支持 GET（显示）和 POST（保存）：

| URL | 作用 |
|---|---|
| `/eq_l` | 编辑/保存左声道 EQ |
| `/eq_r` | 编辑/保存右声道 EQ |

两个页面都带有 `Swap L/R` 复选框。保存任意一个页面都会同时保存：

- 当前声道的 EQ 文本；
- 全局左右交换设置。

保存成功后 ESP32 返回 `OK`，新配置从下一个音频块开始生效，不需要重启。

不再提供 `/eqc`、`/edit` 或任意 NVS 键的读写入口。

## NVS 配置

NVS namespace 为 `storage`：

| 键 | 内容 |
|---|---|
| `eq_l` | 左声道 EQ 文本 |
| `eq_r` | 右声道 EQ 文本 |
| `swap_lr` | `0` / `1`，左右交换 |

旧版本的 `l_config` / `r_config` 以及它们指向的配置键不再读取。升级后如果
`eq_l` / `eq_r` 为空，请在两个编辑页各保存一次配置。旧键会留在 NVS 中，
但不会再被固件读取。

## EQ 配置文件格式

### 简单格式

每行一个滤波器：

```
cf gain q
```

例如：

```
49.00 -5.5 6.589
61.00 1.7 7.352
93.50 9.0 7.496
```

单独一行只有一个数字时表示该声道的延迟（毫秒），例如：

```
1.5
```

左右延迟只使用两者的差值；共同延迟会相互抵消。绝对差值最多 256 帧
（48 kHz 下约 5.33 ms）。

### REW 格式

包含 `Fc`、`Gain`、`Q` 的 REW 滤波器行会被解析，例如：

```
Filter  1: ON  PK       Fc   125.5 Hz  Gain  -5.00 dB  Q 11.776
```

`Filter N: ON None` 等禁用行会被静默忽略。

### 参数限制

- 每声道最多 50 段；
- `0 < cf < 24000 Hz`；
- `0 < q <= 1000`；
- `-120 <= gain <= 120 dB`；
- 每个声道的配置文本不超过 3899 字节（`CONFIG_SIZE = 3900`）。

无效滤波器会被跳过。日志级别默认为 INFO，滤波器构建和解析细节使用 DEBUG，
不会出现在正常串口输出中。

## 声道顺序与 Swap L/R

按 ESP-IDF 的名义 I2S 槽位定义：

- WS 低电平为第一个槽；
- 第一个槽为左声道，第二个槽为右声道；
- 因此默认 `src[0]` 是左、`src[1]` 是右。

实际板卡、ADC/DAC 格式 strap、PCB 走线或音箱接线可能让物理左右反过来。
如果听感确认左右反了，在编辑页勾选 `Swap L/R` 并保存即可：

- 开启时：`eq_l` 作用到槽位 1，`eq_r` 作用到槽位 0；
- 延迟映射同步交换；
- 设置持久化到 NVS `swap_lr`，重启后仍然有效。

建议先用只含左声道的测试音确认物理输出，再决定是否开启交换。

## I2S 数据格式

当前配置：

```c
I2S_STD_MSB_SLOT_DEFAULT_CONFIG(I2S_DATA_BIT_WIDTH_32BIT,
                                I2S_SLOT_MODE_STEREO)
```

- 48 kHz，32-bit 槽位，立体声；
- MSB / 左对齐槽位模式，不是严格的 Philips I2S；
- 24-bit 有效数据位于 bit30..7，低 7 位为 0；
- MCLK 256 fs = 12.288 MHz；
- BCLK 64 fs = 3.072 MHz。

bit30..7 的排布是对参考板一位 I2S 延迟的补偿。若改成原生 Philips 模式，
需要把数据移到 bit31..8，并同步检查 ADC/DAC 的格式 strap 和实际波形。
不要只改其中一侧。

## 热加载

保存 EQ 后：

1. HTTP 任务把文本写入 `eq_l` / `eq_r`，把交换设置写入 `swap_lr`；
2. 设置 `eq_reload_requested`；
3. 音频写任务在左右 EQ 都完成、两个 EQ 任务都空闲的安全点读取新配置；
4. 重建滤波器、重置滤波器状态、重新计算延迟；
5. 下一个音频块开始使用新参数。

重载时当前缓冲区仍使用与它 EQ 处理时一致的交换状态，避免一块缓冲区左右错配。
滤波器状态会在重载时重置，所以保存瞬间可能有轻微瞬态，但不会持续。

## 构建与烧录

需要 ESP-IDF 6.0.2 或兼容版本：

```sh
cd esp32
. $IDF_PATH/export.sh
idf.py build
idf.py -p /dev/ttyUSB0 flash monitor
```

当前 `sdkconfig` 已配置：

- `CONFIG_COMPILER_OPTIMIZATION_PERF=y`（`-O2`）
- `CONFIG_ESP_DEFAULT_CPU_FREQ_MHZ=240`

固件约 840 KiB，应用分区仍有约 18% 余量（具体尺寸随源码变化）。

## 主机测试

不需要 ESP-IDF，使用主机 GCC 即可：

```sh
make -C tests test
```

测试覆盖 24-bit 样本编解码/饱和，以及相对延迟的边界与缓冲索引。

## 性能参考

按 48 kHz、每声道 20 段、`float` 硬件 FPU、240 MHz、`-O2` 估算：

- 每声道约 96 万次 biquad/秒；
- 每声道约占一个核心的 15%~20%；
- 左右 EQ 分别跑在不同核心上；
- Wi-Fi 关闭时，每核总占用约 20%~25%；
- Wi-Fi/HTTP 活跃时核 0 会更高，极端情况下可能出现抖动。

50 段时 EQ 负载约为 20 段的 2.5 倍，余量明显变小。以上是静态估算，建议在
目标板上用 `vTaskGetRunTimeStats` 或 `esp_cpu_get_cycle_count` 实测。

## 已知限制

- AP 和 HTTP 没有认证，只适合可信网络；
- GPIO33 未显式配置内部上下拉，裸触摸焊盘不能直接当数字按钮；
- 一直保持 GPIO33 高电平会周期性地反复开关；
- 热加载在音频写任务中重建滤波器，保存瞬间可能有轻微瞬态；
- Wi-Fi/HTTP 与右声道 EQ、写任务共享核 0，重网络负载时可能出现音频抖动；
- 旧版本的 `l_config` / `r_config` 配置不会自动迁移。
